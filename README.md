# Простая Telegram CRM + мини-приложение

MVP запускается одной кнопкой из PyCharm: `main.py` поднимает Telegram-бота, локальную SQLite базу `crm.sqlite3` и встроенное web-мини-приложение с дашбордами.

Никаких npm/package/backend-серверов отдельно запускать не нужно. Внешние Python-зависимости тоже не нужны.

## Как запустить через PyCharm

1. Откройте проект в PyCharm.
2. Откройте `config.py`.
3. Вставьте токен бота в `BOT_TOKEN`.
4. Вставьте Telegram numeric ID админов в `ADMIN_IDS`.
5. При необходимости отредактируйте `OFFERS` — это пул офферов и выплат.
6. Откройте `main.py` и нажмите Run.
7. Откройте своего бота в Telegram и отправьте `/start`.

Локальный дашборд доступен в браузере: `http://localhost:8080`. Для открытия именно как Telegram Mini App нужен HTTPS-туннель; его URL нужно указать в `WEB_APP_URL` в `config.py`.

## Что лежит в config.py

- `BOT_TOKEN` — токен бота от BotFather.
- `ADMIN_IDS` — список Telegram numeric ID админов.
- `WEB_APP_URL` / `WEB_PORT` — адрес мини-приложения.
- `OFFERS` — пул офферов: ключ, название и выплата с оффера.

## Логика регистрации

- Если Telegram ID пользователя есть в `ADMIN_IDS`, он автоматически становится `admin`.
- Если пользователь не зарегистрирован, бот показывает кнопку **Зарегистрироваться**.
- После нажатия заявка сохраняется в базу со статусом `pending`.
- Админам приходит уведомление в Telegram.
- Админ в меню **Заявки** назначает пользователю роль: `traffic` или `handler`.
- Для роли `traffic` бот дополнительно попросит ввести `traffic_id`.

## Роли и дашборды

### Admin

- видит заявки;
- назначает роли;
- назначает `traffic_id` трафферам;
- видит общий список лидов в мини-приложении;
- видит выплату с оффера, выплату лиду и чистыми;
- может проставить выплату лиду — после этого лид считается засчитанным.

### Traffic

- видит обработчиков на смене;
- выбирает активного обработчика как цель трафика;
- видит свои лиды, которые внесли обработчики по его `traffic_id`;
- вносит бюджет;
- видит CPL: бюджет / количество лидов;
- видит количество засчитанных лидов после выплаты лиду админом.

### Handler

- выходит на смену / завершает смену;
- вручную добавляет лида;
- обязательно указывает `traffic_id`;
- выбирает оффер из пула `OFFERS`;
- видит только своих лидов;
- создаёт заявки на выплату лидам через статус `заявка на выплату`;
- видит конверсию и засчитанных лидов после выплаты админом.

## Статусы лидов

- `в обработке`
- `ждет продукт`
- `выполнение цд`
- `отказал`
- `заявка на выплату`
- `выплачено`

## Почему бот больше не должен спамить дублями

Polling теперь продвигает Telegram `offset` до обработки апдейта. Если отдельная кнопка или сообщение падает с ошибкой, Telegram не присылает этот же апдейт повторно, поэтому бот не отправляет одно и то же сообщение 2-3 раза.
